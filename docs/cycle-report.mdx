title: "Cycle report"
description: "What the model saw, next to what it concluded — in plain English, with links"
---

The journal answers "what did the model decide". It is a poor answer to **"why
should I believe it"**, because the evidence is spread across five nested
objects and a list of prompt lines. The cycle report puts each score next to
the evidence that produced it.

```bash
python -m analysis.cycle_report                 # the most recent cycle
python -m analysis.cycle_report --all           # every cycle in the journal
python -m analysis.cycle_report --ticker NVDA   # one name (repeatable)
```

You do not have to run it. Every cycle renders it automatically to two places:

- **The run's job summary** — open the latest [heartbeat run](https://github.com/omrirulf/Algo-Trading-/actions/workflows/heartbeat.yml) and read it on the page.
- **`logs/cycle_report.md`**, committed to the repository — browsable on a
  phone, and diffable between cycles.

The four enrichment sections are shown as **the prose the model read**, rebuilt
from what the journal stored — not as a table of raw fields. The prose carries
the interpretation the numbers alone do not ("50d above 200d", "92% of the way
up the range"), and it is literally what was being judged. A line the report
cannot rebuild (an older schema, a malformed value) falls back to a field
table rather than disappearing.

## Every name says what it is

A ticker is an identifier, not a name. A report that says only `NVO` asks its
reader to hold thirty-five symbols in their head; one that says **Novo
Nordisk** does not. `config/instruments.py` carries a `DISPLAY_NAMES` map for
the whole watchlist and a `sleeve_label()` derived from `kind_for()`, and the
report puts both on every heading:

```
### US government bonds, 20+ years (TLT) · Index fund — BEARISH, confidence 0.45
```

<Note>
  The names are a static map, not a yfinance lookup. The watchlist is fixed and
  curated, so a name is a fact about the list itself — and the report has to
  work offline from a journal, with no network call available to it.
</Note>

The sleeve tag is repeated on every heading even though the tickers are also
**grouped** under `## Companies`, `## Whole-market funds`, `## Sector and
country funds` and `## Commodities`: a heading copied or linked on its own
still has to say what it is about. An
unnamed ticker falls back to its own symbol, and an unrecognised one labels as
`Company` — the same fail-closed default `kind_for()` uses for the position
cap, never the widest one.

The summary table at the top counts each group. It exists because a flat list
ordered by conviction cannot answer *"did we even look at the commodities
today"*, which turned out to be the first question a reader asks — and a cycle
where every commodity came back NEUTRAL looks identical, in a list sorted by
conviction, to one where none was checked.

## Written to be read by a person, not a developer

The framing text, the section titles and the verdict lines are written at
roughly **B1–B2 English** — short sentences, common words, no idioms — and a
word list at the end covers the terms that have no simpler synonym: RSI, MACD,
P/E, ATR, stop-loss, insider. The prompt's own headings are shouted
abbreviations aimed at a model (`ANALYST & INSTITUTIONAL VIEW`); the report
uses "What analysts and big funds say".

<Warning>
  The model's **rationale** and **key factors** are reproduced verbatim, and
  the report says so where it prints them. Those are the evidence; a
  plain-English paraphrase of them would be a summary of a summary, and the
  thing being checked would no longer be in the document.
</Warning>

Renaming a report section cannot touch the prompt — the prompt builds its own
headings in `orchestrator/context.py`, and the byte-identity test pins that.
The timestamp leads with Israel time and keeps UTC beside it, because the
journal's own stamps are UTC and have to stay checkable against it.

## The links are new, and the prompt did not change

Headlines reach the model as `title — snippet (source, when)`. The URL was
being parsed out of the Bright Data response and **thrown away**, which meant a
signal could cite a story nobody could go and read.

Links are now kept — but deliberately *beside* the prompt line, in
`context.sources`, not inside it:

<Note>
  The prompt is the input every [replay](/historical-replay) and
  [sanity](/signal-sanity) baseline was measured against. Adding a URL to the
  text the model reads would have changed the token stream and quietly
  invalidated the comparison. `TickerContext.as_prompt()` is byte-identical to
  what it was before; a test pins that.
</Note>

A cycle journalled before this existed still renders — it says so, and falls
back to the plain headline text.

### The link is Google's, not the publisher's

Google's news results usually hand back their own redirect stub
(`/goto?url=<encrypted blob>`) rather than the article's address, and the
parser returns it with no origin — which makes it resolve against whatever
page renders it, i.e. nowhere. The first live cycle stored 100 of 176 links
in that shape.

`news.absolute_url()` now gives every link an origin at parse time, and the
report repairs older journal lines the same way on the way out. One click
still lands on the story; the stub's payload is encrypted, so recovering the
publisher's URL directly would cost an HTTP round trip per headline — 350 of
them on a 35-ticker cycle — which is not a trade worth making for a link that
already works.

## What it cannot tell you

<Warning>
  This is a record of the **inputs**, not a verdict on the output. A signal
  with beautiful-looking evidence can still be wrong, and the report has no
  opinion about that. Only [scoring](/scoring) against realised returns can say
  whether the signals are worth trading.
</Warning>

The snapshots are rendered from what the journal stored, so a dimension that
was unavailable shows as unavailable rather than as a neutral reading — the
same distinction the prompt itself makes.
