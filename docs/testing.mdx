```bash
pytest tests/ -v
```

Every test runs with no Alpaca keys, no Bright Data token, no Anthropic key,
and no network access. `tests/conftest.py` provides `FakeBroker` and
`FakeMarketData`; the news and LLM tests use `httpx.MockTransport` and a
fake Anthropic client respectively. CI runs the same suite with the process
environment stripped, as an extra check that nothing quietly depends on a
real credential being present.

## What each file proves

| File | Tests | Proves |
|---|---|---|
| `test_risk_engine.py` | 34 | The 5% cap holds pre- and post-rounding, existing exposure is counted, fractional shares are never returned, stop math is correct for both long and short, ATR-sanity rejects degenerate data. |
| `test_schemas.py` | 55 | `LLMSignal` rejects extra fields, enforces every bound (conviction range, ticker pattern, rationale length), and normalizes tickers to uppercase. |
| `test_market_data.py` | 6 | The Wilder ATR implementation matches a reference calculation, including gap and NaN handling. |
| `test_execution_engine.py` | 16 | The full nine-step decision path, every guardrail gate, and that broker/market-data errors become `ERROR` results rather than exceptions. |
| `test_webhook.py` | 12 | HTTP auth (401 on a bad secret), 422 on smuggled fields, that importing `app.main` needs no credentials, and correct handling of rejections. |
| `test_heartbeat.py` | 8 | The orchestrator can only ever send the closed signal shape; missing credentials are logged per-ticker without killing the scheduler. |
| `test_news.py` | 19 | Bright Data request shape, response parsing (including the wrapped and fallback-key shapes), and every `NewsFetchError` condition. |
| `test_llm.py` | 25 | Schema derivation can't drift from `LLMSignal`, the request shape (model, effort, schema), every `LLMError` condition, and the refusal fallback — including that a declining model's partial text is never mistaken for the answer. |

## A test suite is only as good as its negative cases

A recurring pattern in this codebase: when a test claims a guardrail holds,
there's a companion test proving the *opposite* input trips it. For example,
`test_risk_engine.py` doesn't just assert the 5% cap is respected on a
compliant input — it asserts that an input designed to overflow the cap
after rounding raises `RiskViolation`.

The same discipline was applied manually to the fallback logic while
building it: the switch-point-reading logic in `orchestrator/llm.py` was
temporarily reverted to prove `test_answer_is_taken_from_the_model_that_did_not_decline`
actually fails without it, before restoring the fix.

## Running a single file

```bash
pytest tests/test_risk_engine.py -v
```

## Running with coverage

```bash
pytest tests/ --cov=app --cov=orchestrator --cov=config
```

<Note>
  Coverage isn't wired into CI — the guardrail invariants job (see
  [Continuous Integration](/continuous-integration)) checks structural
  properties that line coverage can't, like "does anything outside
  `broker_client.py` import the Alpaca SDK."
</Note>
