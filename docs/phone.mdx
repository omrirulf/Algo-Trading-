Two things reach the phone after every cycle, and neither needs an account,
a server, or a login.

## The desk as an app

The dashboard is a static page deployed to GitHub Pages by the `pages`
workflow after every journal commit:

**https://omrirulf.github.io/Algo-Trading-/**

<Steps>
  <Step title="Open it once in Chrome">
    The page shows the record: every position against its stop, the risk caps
    and how full they are, today's funnel and cost, and the alarms. It
    explains none of it: each part carries a small link to the page of these
    docs that does.
  </Step>
  <Step title="Add to Home screen">
    Chrome's menu → *Add to Home screen* (or the install banner). The page
    becomes an app with its own icon, full screen, no browser bar.
  </Step>
  <Step title="That is all">
    Online, the app reads `logs/book.json` straight from the public repository
    every five minutes and whenever it comes to the front. Offline, it opens
    on the last copy it saved, and says so.
  </Step>
</Steps>

The page embeds the snapshot at build time (`dashboard/build.py --site`), so
even its first open shows something. The service worker keeps the page itself
openable with no network. Nothing on the page is a credential: the repository
is public, so the page is too.

<Note>
Marks are what the position manager saw on its last pass, not live quotes.
The page is a view of the record, rebuilt from the journal and the audit log;
it never asks the broker anything.
</Note>

## The brief as a push notification

The heartbeat writes `logs/brief.txt` after the book snapshot: the worst
thing in the record first, then equity, positions, what was traded, who
started the day ("Started by supabase-cron at 14:41 UTC (1 min after
14:40)", with a warning when a backup had to), what the Supabase starter's
own request got back and when the archive last took a push (see
[the Supabase starter](/deployment#the-supabase-starter)), what closed, any
position without a stop on record, the other alarms, and the cycle's cost. The same step then posts it to [ntfy](https://ntfy.sh), a free
push service with an Android app and no account.

<Steps>
  <Step title="Install ntfy on the phone">
    Google Play → *ntfy*. Open it, tap **+**, and subscribe to a topic name
    you invent: long and random, for example `algo-desk-` followed by twelve
    letters and digits. Anyone who knows the name can read or send, so treat
    it like a password.
  </Step>
  <Step title="Store the same name as a repository secret">
    GitHub → Settings → Secrets and variables → Actions → **NTFY_TOPIC**.
    The push steps read it from there and nowhere else.
  </Step>
  <Step title="Wait for the next cycle">
    Until the secret exists every push step says *no phone configured* and
    sends nothing. The first cycle after it exists sends the brief.
  </Step>
</Steps>

What arrives, and when:

| Notification | Sent by | Priority |
|---|---|---|
| The day's brief (🟢 / 🟡 / 🔴 headline) | `heartbeat`, the moment the brief is written | urgent when the headline is 🔴 |
| *The trading cycle run failed* | `heartbeat`, when the run goes red for a reason the brief did not carry | urgent |
| *⚠️ Archive push to Supabase failed* | `heartbeat`, the same day the push to the Supabase archive fails (not when it is only not configured: that is a daily warning in the brief) | high |
| *A data source stopped answering* | `data sources`, when the morning probe fails | high |
| *Weekly report* (drift, risk digest, concentration when new) | `heartbeat`, on the week's first cycle day, after the journal is committed; see [Weekly and monthly reports](/weekly-report) | normal |
| *No shekel rate table tonight* / *Bank of Israel not reached tonight* | `scoring-prices`, after a green shadow funds run on `main` whose hand-over has no rate table, or one in which none of the last three days came from the Bank of Israel; see [After tax and in shekels](/after-tax) | normal |
| *The shadow funds run failed tonight* | `scoring-prices`, when the night's shadow funds run on `main` ends red (it keeps no rate table then) | normal |
| *Scoring prices not archived* | `scoring-prices`, when the copy to the Supabase archive fails | normal |
| *Shadow universe stopped at its cost cap* | `shadow universe`, when the day's model and news cost reaches the $1.50 cap (from 2027-01-01) | normal |
| *Monthly check-in* (a fixed checklist, no personal number) | `monthly coach`, on the first working day of each month from November 2026 | low |

The topic is the only secret and it never appears in a URL or a log: the
message is posted as JSON to ntfy's root, and the temporary file that carried
it is removed. The **phone topic check** workflow says whether the name is
long and random — only characters ntfy accepts, at least 20 in all, at least
12 after any readable prefix with letters and digits mixed, no character more
than a quarter of them, no year and no common word in them, about 60 bits or
more. Length and patterns cannot prove a name is random, so a name typed by
hand should be replaced with a generated one. It
prints only the verdict, never the name (the log is public, so a weak name's
failing test is not named either). It runs on any pull request that changes
it, and by hand from the Actions tab once it is on `main`. If a freshly
generated name is warned about, generate another.
ntfy.sh is public, so nothing personal is ever pushed; moving to a private
channel is on the [before real money checklist](/next-steps#before-real-money-the-checklist). A push step never fails the run; the run's verdict is the
cycle's.

Tapping a notification opens the desk; tapping the weekly report opens its full
text in the repository (`logs/weekly/<week>.md`). A drift alert also heads that
day's brief, as a warning.
